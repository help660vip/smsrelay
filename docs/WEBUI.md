# WebUI 快速上手

v0.2.1 的本地管理页可以在 Magisk 手机上通过 KsuWebUIStandalone 打开。模块自身仍是 ZIP，Magisk 的「操作」菜单保留。KsuWebUI 只用于打开页面，关闭页面后，短信、响铃和应用通知仍由 Magisk 服务处理。

1. 安装新版模块 ZIP，重启后打开 KsuWebUIStandalone，允许它使用 Magisk root 后选 **smsrelay**。
2. 在「配置」设置企业微信和／或 SMTP，再勾选每项功能要用的渠道。旧版配置与队列保留，来电和应用通知默认关闭。
3. 开启应用通知时，搜索应用名称或包名，从结果中选择。页面通过系统读取应用名称，包名用来匹配。还可以排除指定的通知类别。
4. 先用「规则预览」确认匹配。「测试这条路线」会将标有测试字样的模拟消息送往所选渠道，需要再次确认。
5. 用「收发记录」查事件、失败和渠道进度，用「运行日志」查服务问题或导出脱敏诊断。

## 来电和应用通知

- 来电在进入响铃状态时提醒一次，每张 SIM 独立判断。v0.2.1 使用系统带号码的回调，ROM、运营商或来电方未提供号码时显示「未知号码」。恢复后已经过期的响铃任务会显示为过期；默认有效期为十分钟。
- 新短信和来电会记录接收卡、运营商和系统返回的本机号码。换卡后使用新的订阅信息，历史保留事件发生时的卡信息。
- 应用通知读取系统提供的应用名、标题和正文。部分应用只发通用提示，或者系统在锁屏、隐私模式下隐藏内容，详情会相应缺少正文。当前监听 Android 主用户的应用通知。
- 邮件标题和两条渠道的文本使用同一条转发标记。应用通知带回标记时会记为回环拦截。某个客户端丢弃标记时，可用应用白名单和类别排除规则拦截它。
- 同一个系统通知反复更新时合并重复的内容。不同通知标识的同文消息仍可入队。发送间隔造成的延后会记在时间线上。渠道、功能或原目标关闭时，旧任务暂缓，原目标重新启用后可继续处理；更换收件人不会把积压转发给新收件人。

## 记录与配置

K40 开机后要先解锁一次，系统短信数据库才可用。开机脚本最多等约三分钟。超过等待时间时，解锁后在 KsuWebUI 概览或 Magisk「操作」中启动服务。

事件详情在手机私有目录保留正文、来源、收取时间、每个渠道的尝试与响应。已完成事件的完整历史默认保留七天。旧版升级前的发送记录无法补建。使用「分享脱敏记录」会去掉来源、正文、标题、包名、类别和接收卡信息；分享前可在页面预览。运行日志独立保存，不记录转发正文。

WebUI 保存到 `/data/adb/smsrelay/config.json` 的对应字段，保留其他中文注释。留空 Webhook／SMTP 密码输入框会保留已有值。旧配置缺少 `routing.sms` 时沿用原来的顶层 `enabled`，设置三项独立开关后使用 `routing`。

## 验证与兼容

| 项目 | 已验证范围 |
| --- | --- |
| 构建 | DEX 最低 API 25，PowerShell 构建纯 Magisk ZIP |
| 短信与队列 | K40 Android 13 隔离离线回归，覆盖持久状态、失败恢复、路由和过滤 |
| WebUI | Chrome 412 px 和 1024 px 视口，使用异步系统桥接回归切换、保存、规则预览、历史和脱敏分享。首屏和保存各只发一个请求 |
| K40 新监听 | 两个 SIM 订阅均收到初始状态。Android 系统发出的合成通知经 root 监听采集，两条渠道任务在隔离环境中分别入队 |
| K40 短时空闲 | 锁屏、ADB 连接、无待发任务，20 秒采样中 Provider 查询、发送计数及核心和监督进程 CPU 时钟滴答增量均为 0。两个采样点均未持有模块唤醒锁，也没有注册网络回调 |
| 其他待验收范围 | 其他 ROM 和 Android 版本、长期待机 |

在仓库根目录构建后，可以运行 `./scripts/test-webui-device.ps1 -Serial <序列号> -Tools <工具目录>`。脚本在设备的临时目录启动隔离实例，只用占位配置和合成通知。验证录入、预览、入队、直接连通性测试和脱敏，实际网络发送处于隔离状态。附加 `-IdleSeconds 20` 可做两次空闲采样。
