测试对象：Redmi K40，M2012K11AC / alioth，HyperOS 1.0.10.0，Android 13 / API 33，内核 4.19.157；Magisk Alpha 30700。root UID 0、SELinux Enforcing。没有安装 APK，没有调整 SELinux／Doze，没有清空或修改系统短信，没有修改整机时钟。

## 离线测试

主机测试执行 577 项断言，含 200 组固定随机种子的 Unicode 分段案例。设备隔离测试通过 32 项断言，覆盖首次空收件箱、已有历史、批量新短信、重复通知、低 ID、逐渠道状态、异常 SENDING 恢复、正文保留、配置拒绝、日志及数据库边界。

```powershell
.\scripts\test-host.ps1 -Tools E:\smsrelay\tools
.\scripts\test-device-offline.ps1 -Serial <指定设备序列号> -Tools E:\smsrelay\tools
```

设备测试只使用 `/data/local/tmp/smsrelay-test-<随机标识>`，不接触系统短信库，不调用通知或短信 API。测试目录保留用于复查；测试结束后可明确删除对应目录。

## 短信网关与真实内容边界

截至正式目录验收，实际使用 6 次短信 API 请求（其中 1 次被来源格式限制拒绝），低于 100 次上限。请求计数保存在仓库外，只向已授权的固定测试目标发合成短信。初次字母来源被拒绝后按返回要求改用数字测试来源，没有伪装银行。

本次网关在特殊字符测试中对引号添加了反斜线、将 Emoji 转为问号；一条较长的验证码演示在 Provider 中只有 65 字符，末尾标记已截断。API 返回成功不能当作设备收到了原始完整输入。短版演示则完整到达。模块转发以 Provider 实际正文为准；长短信和完整 Unicode 的采集／分段主要通过隔离测试覆盖，不能把这些测试写成该短信网关支持所有长短信。

没有主动向真实银行请求验证码，未冒充银行来源。仿真验证码通过不能证明所有银行私有存储、反垃圾拦截或 ROM 特殊收件路径均可读取。

## 空闲行为

两次采样（隔离服务 88 秒、正式安装模块 190 秒）在无待发任务、没有新短信期间进行，USB／ADB 保持连接：

- 核心和监督进程 CPU ticks 增量均为 0。
- Provider 查询和网络发送计数增量均为 0。
- 核心主线程位于 epoll 等待；Binder 线程位于 Binder 等待；发送工作线程位于 futex 等待；控制线程阻塞于 socket。
- 队列清空后网络回调注销，状态无工作唤醒锁。
- 专用 `smsrelay:work` 记录中的实际采集／发送锁按工作完成释放，无持续持锁。

采样工具是主机发起的两个有限快照，不属于模块常驻功能。root UID 统计会混入其他工作，因此这里使用本模块具体 PID 的 CPU 和线程数据。USB 会影响整机深睡，短时证据不能换算固定 mAh／天，也不能证明所有长期异常条件下绝对零耗电。

## 未验证和限制

- 其他 Android 系统／ROM、ARM32、x86／x86_64 实际运行；没有把 K40 测试外推成全版本兼容。
- 真实网络从完全断开到恢复的系统事件链；已验证回调注册与按队列注销，故障等待和恢复用隔离状态注入覆盖。
- 物理换卡、新订阅创建／删除后实际收件；已有事件实现，当前双卡识别已实测。
- 冷启动首次解锁前、整机重启开机自启；没有擅自重启日常使用中的手机。
- Magisk 图形页面“操作”按钮的点击呈现；`action.sh` 规范与设备实际菜单程序已核对，未用“有 TTY”冒充可键盘交互。
- 服务端已接受但响应丢失时仍可能重复；SMTP 接受与收件端通知分别描述。
